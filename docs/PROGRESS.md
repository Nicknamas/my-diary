# Прогресс проектирования Indi

Обновлено: 2026-10-21

## Где мы сейчас

**Метод:** Event Storming в Excalidraw — `docs/event-storming/design.excalidraw`.
**Первая цепочка:** создание проекта → сборка → публикация → запуск у читателя.

## Принятые решения

### Система

- Бэкенд на микросервисах, языки разные осознанно (исследовательская цель): ядро на TypeScript/Node, отдельные сервисы на Go или Python.

### Продукт и предметная область

- Ответы на посты — обычные комментарии.
- «Посты о проекте» — любые упоминания проекта.
- У проекта одна активная сборка. Во время замены старая какое-то время хранится.
- У каждого пользователя 5 приглашений. Пригласивший отвечает за приглашённых, модерация идёт через дерево приглашений, явных модераторов нет.
- Аккаунт удаляется не сразу, а через какое-то время.

### Цепочка «проект»

- До публикации проект существует как черновик.
- Редактирование опубликованного проекта создаёт черновик изменений, а читатели до публикации видят старую версию.
- Публикация изменений — отдельное событие. Подписчикам приходит «Проект обновлён».
- Читатель, у которого проект открыт во время замены, видит «Проект обновился, перезапустить?».
- При редактировании проект может сменить тип: ссылка ↔ сборка. Старая сборка удаляется, только если она была.
- Отказ по ссылке — одно событие с причиной в данных. После отказа автору всегда предлагают загрузить сборку.
- Неудачная проверка сборки — одно событие с причиной: нет `index.html`, слишком большой размер после распаковки, повреждённый архив.
- Вредные пути в архиве — отдельное событие. Оно считается нарушением, и пригласившего уведомляют.
- Слишком большой архив — мгновенный отказ команды, а не событие. Сервер проверяет размер в любом случае.
- Запуски считаются по переходам в проект, неважно, успешным или нет.
- Если проект не загрузился у читателей, автора уведомляют.
- Превью: картинку загружает автор по желанию, если её нет, показывается название.
- OG-карточка собирается заранее, при публикации и обновлении, и пересобирается при смене имени автора.

## Архитектура фронта

Модули по доменам, а не FSD: в FSD один домен размазан по 5–6 слоям, и новичку тяжело в нём ориентироваться.

### Уровни

```
core/         — корень приложения и рамки (layouts): хедер, сайдбар, таббар
pages/        — сборки экранов из блоков доменов
domains/      — домены и поддомены
src/shared/   — глобальные утилиты, composables, типы: используются где угодно
UI-кит        — отдельный npm-пакет
```

Импорт только вниз: `core → pages → domains → src/shared`.

### Домен

```
domains/<name>/
  api/       — read-слой и мутации
  model/     — модели из read-слоя + мутации + черновики
  ui/        — глупые компоненты: только props и emits
  block/     — умные блоки, которые домен отдаёт в pages
  shared/    — константы, схемы, типы, утилиты домена
  index.ts   — публичный API
```

- Экранов в домене нет, их собирают `pages`.
- Снаружи домена — только через `index.ts`. Граф зависимостей между доменами явный и без циклов.
- Read-слой — composables поверх Pinia Colada: берут данные из запроса, добавляют вычисляемые поля и отдают всё вместе.
- `block` может читать из `api` напрямую, если нужен только read-слой. Мутации и черновики — через `model`.
- Composables вызываются только в блоках. Список читает данные один раз и раздаёт их карточкам через props.
- Тяжёлые вычисления выносятся в общий экземпляр (`defineQuery` в Pinia Colada или `createSharedComposable` из VueUse), но только после замера.

### Поддомены

- Похожие независимые модули группируются под общим доменом-родителем.
- Общее для поддоменов лежит в `core` родителя, выбор поддомена по типу — в `index.ts` родителя.
- Соседние поддомены не импортируют друг друга.

### Страницы

- Выбранные сущности хранятся в URL (например, `/projects/:projectId`).
- Блоки доменов получают `id` и сами загружают свои данные.
- Страницы друг от друга не зависят.

### Алиасы

- `@shared` — только глобальный `src/shared`.
- `@domains/*` → `src/domains/*`: одно правило с маской на все домены (`@domains/feed/shared`).

### UI-кит

- Отдельный npm-пакет, публикуется в реестр.
- Локальная разработка — через `yalc` или `npm link`, версии — через Changesets.
- `vue` в ките объявлен как `peerDependency`.

Правила импорта для линтера — в [eslint-rules.md](eslint-rules.md).

## Открытые вопросы

### На доске (горячие точки)

- Как платформа узнаёт об успехе или ошибке запуска?
- Сколько хранить старую сборку после обновления?
- Когда уведомлять автора об ошибках загрузки (порог, как отличить проблемы самого читателя)?

### Из обсуждений

- Гость — это отдельный актор? Считаются ли его переходы? Решить на 5-м проходе.
- Восстановление, если потеряны все ключи и коды: варианты обсуждали (без восстановления, через пригласившего с периодом ожидания, хранители M из N, привязанный GitHub, почта), решения нет.
- Правила модерации через дерево приглашений: что считать нарушением, как глубоко идёт ответственность и что бывает за повторные нарушения.

### Фронт

- Сколько рамок в `core`: навигация есть не на всех экранах (вход, запуск проекта, гостевой вид идут без сайдбара и таббара).
- Правая колонка, своя у каждого экрана: именованные представления Vue Router (`<RouterView name="aside" />`) или иначе.
- Где живут токены и темы: в UI-ките или отдельно.
- Какой реестр для UI-кита: публичный npm, GitHub Packages или свой (Verdaccio).
- Как называть локальное состояние формы, чтобы не путать его с серверным черновиком проекта.

### Мелкие правки на доске

- Опечатка «преовью».
- Стрелку к удалению старой сборки вести от «обновлён», а не от OG-карточки.
- Связать дорожку «Читатель» с публикацией.

## Отложено на «парковку» (отдельные цепочки)

- Вход, приглашения, восстановление доступа.
- Лента, посты, комментарии, лайки, закладки.
- Модерация.
- Удаление аккаунта.

## Кандидаты в ADR

- Стек каждого сервиса, монорепозиторий или нет.
- Хостинг сборок и изоляция: отдельный домен, `iframe sandbox`, CSP.
- Путь загрузки: через API или по временной ссылке (presigned URL) прямо в хранилище.
- Авторизация: passkey и коды восстановления.
- OG-карточки заранее (решение уже принято, осталось его записать).
- Канал от сервера к открытой странице (SSE, WebSocket или опрос) для «Проект обновлён» и баннера «новые посты».
- `vue: beta` (Vapor) в продакшене.
- Архитектура фронта: модули по доменам вместо FSD (решение принято, осталось записать).
- Pinia Colada для данных с сервера (выбрано, осталось записать).
- UI-кит отдельным пакетом и выбор реестра.
